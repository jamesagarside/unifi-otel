# SYNTHETIC. The third axis from issue #25: the same payload over
# RFC3164/UDP and over RFC5424/TCP.
#
# MATCHED-PAIR FILE. Frames come in adjacent pairs: the RFC3164 frame
# first (replayed over UDP to syslog/unifi_udp), the RFC5424 frame second
# (replayed over TCP to syslog/unifi_tcp). The harness routes each frame
# by its own syntax -- "<PRI>1 " means RFC5424 -- so the two receivers are
# both exercised from one file.
#
# WHY THIS AXIS EXISTS: RFC5424 has no doubled-hostname pathology, so
# every RFC5424 frame takes what is effectively the single-hostname path
# -- the exact path issue #24 showed was silently degraded. It was never
# replayed before.
#
# HONESTY NOTE: no real non-CEF RFC5424 device frame has ever been seen by
# this project. UniFi's SIEM Server emits RFC5424 over TCP, but every
# frame observed on that path has been CEF. Whether UniFi emits non-CEF
# device syslog over 5424 at all is an OPEN QUESTION (#25). Pairs 1-4
# below are therefore inventions testing a receiver, not a record of
# vendor behaviour.
#
