# SYNTHETIC, and the most load-bearing synthetic frame in this corpus.

# The payload is the real one from real-linkcheck, byte for byte. What
# is invented is the FRAMING: every datagram carries a full RFC3164
# header, the doubled hostname and the linkcheck tag, where the captured
# frame carries them on the first datagram only
#
# Why it exists. A gateway that re-heads every line of a multi-line
# message defeats any predicate keyed on "a continuation has no header",
# and the issue #9 operator was keyed on exactly that. Replayed against
# the shipped config before the fix, this frame came back as six
# separate records plus a seventh stranded head, and two of these frames
# in a row came back as ONE record holding the two head lines glued
# together -- the closing brace could never match, so the batch never
# closed. Both were measured, not predicted; see issue #34
#
# What it is NOT. It is not a capture. No re-headed linkcheck frame has
# been scrubbed and contributed to this project, so the line count, the
# payload keys and the head line's text here are all the OLD frame's,
# and only the framing is new. A real one is on the wanted list in
# docs/contributing-samples -- and it is worth having precisely because
# the head line is the part most likely to differ
#
# Keep real-linkcheck as well. The two frames are the two shapes, and a
# predicate that handles one and not the other is the bug both times
#
# Everything between the markers is a wire unit, verbatim and in order
